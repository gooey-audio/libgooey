# Make Resonator and Twin Core selectable channel instruments

This ExecPlan is a living document. Maintain it as work proceeds under `.agent/PLANS.md`.

## Purpose / Big Picture

A host using `GooeyEngine` currently cannot put the two new percussion voices in a channel. After this work, it can select Resonator or Twin Core in any of the five existing slots and use the slot's sequencer, velocity, mixer, parameter locks, and LFOs. A host can prove this by selecting either type, programming step zero, rendering a buffer, and hearing nonzero audio. The generated C header must also parse so Swift can import the module.

## Decision Log

- Decision: Keep five channel slots and report seven selectable types; expose a separate channel-count function.
  Rationale: Hosts need both counts, and growing the render arrays would create phantom slots.
  Date/Author: 2026-09-28, Codex.
- Decision: Keep LFO target behavior consistent with existing drums: the route writes a live target after locks, and the channel getter reports the locked base.
  Rationale: `tests/param_locks.rs` documents and verifies this behavior.
  Date/Author: 2026-09-28, Codex.
- Decision: Apply an independent, smoothed ±12-semitone tuning offset to each new voice's computed base frequency.
  Rationale: This preserves indexed pitch/tune values and survives factory preset replacement.
  Date/Author: 2026-09-28, Codex.

## Context and Orientation

`src/ffi.rs` owns five `VoiceStrip` objects: four in `DrumKit` and one bass strip. Each strip contains an instrument, sequencer, preset blender, mixer controls, and parameter locks. The render loop triggers strips at sequencer sample positions and sums their output into the existing mixer graph. `src/instruments/percussion_engine.rs` already selects factory Resonator and Twin Core voices but is exposed only through a standalone handle. `src/instruments/resonator_voice.rs` and `src/instruments/twin_core_perc.rs` contain the synthesis and smoothed parameters. `build.rs` generates the ignored `include/gooey.h` using cbindgen. `.github/workflows/tests.yml` runs Rust tests, while `.github/workflows/ios-release.yml` builds the archive on a tag.

An index parameter is a numeric control ID in the C API. A lock stores a base value that XY blending cannot replace. An LFO is a low-frequency oscillator that changes a live parameter target every render sample. A preset rebuilds a voice from a named factory patch. These terms refer to the functions and structs in the files above.

## Plan of Work

First, extend `ChannelInstrument` in `src/ffi.rs` with Resonator and Twin Core variants using `PercussionEngine` set to the corresponding kind. Add their direct setter, getter, trigger, tick, and LFO dispatch without allocating on the render path. Set `INSTRUMENT_COUNT` to seven and leave `NUM_INSTRUMENTS` at five; expose `gooey_engine_channel_count`. Use a blender variant that performs no work for these types, disable blending on type selection, and skip per-step blend application and parameter snapping for them.

Second, add channel parameter IDs 0–8 for Resonator and 0–13 for Twin Core, including body and noise mode IDs 12 and 13. Continuous controls take normalized 0–1 values. Modes take floating 0–2 values, rounded and clamped to an enum; the underlying voice already latches pending modes at trigger. Add count functions and a channel preset setter/getter using the five existing `PercussionPreset` factories. Invalid channel, type, or preset produces `false` or `u32::MAX`; a successful preset load clears locks and preserves the strip and tuning.

Third, add a neutral-at-0.5 smoothed tuning offset to the two voice implementations. Multiply the computed base frequency by `2^((tuning - 0.5) * 2)` before the existing frequency clamp. Keep the offset separate from indexed pitch/tune and copy its target when replacing a factory voice. Change Twin Core's normalized conversion for tune, length, FM decay, noise filter, and noise decay to `min * (max/min)^normalized`, with the logarithmic inverse for getters. Keep other mappings linear. Document ranges, including the noise-filter maximum of 0.45 times sample rate, in C-exported constants' comments.

Finally, remove `#[repr(C)]` from the two opaque standalone FFI handles. Add `clang -fsyntax-only -x c include/gooey.h` after a build in tests and release CI. Add integration tests in `tests/` for selection, audible sequencer output and velocity, gain/mute/solo/peaks, parameter reads and locks, LFOs, presets, tuning, modes, blend no-ops, curves, and invalid inputs.

## Validation and Acceptance

New tests should demonstrate that selecting type IDs 5 and 6 on an existing channel returns the same IDs and produces finite, nonzero audio when a programmed sequencer step fires. A smaller step velocity should reduce measured output. Mixer gain/mute/solo and peak reads should work on those channels. All parameter indices should round-trip, with mode values returning rounded IDs. A lock should survive triggers and a channel preset load should clear it without changing mixer, pattern, or tuning. XY calls and step overrides should leave parameters unchanged. An LFO should change the live target while `get_channel_param` reports the lock. Tuning endpoints should produce frequency ratios of one-half and two relative to neutral. Exponential map endpoints and interior values should round-trip. The generated C header should parse on both test and release CI.
